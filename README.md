面向《星际公民》玩家社区的 Windows 桌面工具，把主舰队、社区组织、交易大厅、好友、房间和游戏浮层放在同一个应用里。当前为公开测试版。

## 星海舰桥对游戏和电脑做了什么

这一节如实列出应用和游戏、Windows 打交道的方式。

**不做的事：**

- 不向游戏进程注入代码；
- 不使用键盘钩子，不 Hook 游戏的渲染管线或输入；
- 不读取或修改游戏内存；
- 不拦截或改写游戏网络通信；
- 不修改《星际公民》客户端文件；
- 不从游戏画面识别文字；
- 不发送模拟按键和宏，不替玩家操作、瞄准或移动。

**会做的事：**

| 行为 | 具体做法 |
| --- | --- |
| 读取日志 | 只读用户选择的 `Game.log`，游戏写入时用共享方式打开。 |
| 判断游戏是否运行 | 查询 Windows 进程列表，并以受限查询权限打开游戏进程，只取程序路径。不读内存。 |
| 判断游戏是否在前台 | 查询当前前台窗口。 |
| 监听快捷键 | Alt+O、Alt+M、Ctrl+Alt+Y/N 默认只监听按键，**不拦截，游戏和其他程序也会收到这些键**。如果某个键在游戏里绑了操作，会同时触发；在游戏聊天框里按 Alt+O，字母 o 会输入到聊天框。设置里可以改用系统热键（默认关闭）。 |
| 打开游戏内菜单 | 按 Alt+M 打开菜单时，如果 Windows 拒绝切换焦点，会短暂把菜单窗口的线程接入游戏窗口的输入队列（`AttachThreadInput`），切换后立即解除。它不注入游戏，不读写游戏内存，也不发送按键。 |
| 绘制浮层 | 独立的透明置顶窗口，正常显示时不激活、鼠标穿透。不修改游戏画面。 |

CIG 和反作弊程序如何看待这些行为，我们无法代为判定，请自行评估。以上是当前代码的实现方式，**不是 CIG、RSI 或反作弊系统作出的许可、认证或豁免**。应用内的同样说明在“帮助与支持 › 说明与声明”。

## `Game.log` 识别

用户在“账号与识别”中自动扫描或手动选择 `StarCitizen\LIVE\Game.log`。应用启动时只回看日志尾部恢复近期状态，之后持续读取新增的行，把匹配到的行整理成事件，再按证据强弱和时间推断当前状态。结果先用于本地界面和浮层；是否对外同步，由账号状态和用户设置决定。完整算法见 [Game.log 识别算法](docs/GAME_LOG_LISTENING_ALGORITHM.md)。

它可以辅助识别：本地游戏身份、游戏是否运行、服务器分线、当前飞船、地点证据和部分游戏事件。

“已识别”不代表来自 CIG 的权威接口，只应作为协作参考：

- 游戏更新可能随时改变日志格式；
- 某些行为不会写入日志；日志可能延迟、缺失、重复、乱序或被截断；
- 导航目标不等于实际抵达；飞船离座不一定代表离船；
- 低、中、高可信度是应用的经验分级，不是官方数据，也不是统计概率。

请勿仅凭识别结果做出涉及游戏资产、账号或交易的重要决定。

## 浮层的兼容性限制

- 独占全屏、Windows 合成策略、显示缩放、多显示器和 HDR 可能影响浮层位置或可见性；
- 显卡驱动、Windows 更新、录屏软件及其他浮层可能产生层级冲突、闪烁、黑屏或渲染失败；
- 快捷键可能与游戏、输入法或其他软件冲突，也可能被安全软件阻止；
- 低配置设备可能掉帧或延迟；
- 游戏焦点识别可能短暂误判；
- 未来的游戏、反作弊或 Windows 策略可能使当前实现无法继续使用。

出现异常时请先关闭浮层；仍有问题时完全退出星海舰桥，并在重新使用前查看最新版本说明。

## 数据、联网与隐私

- 应用不是纯离线软件。登录、好友、舰队、组织、房间、消息、交易、公开资料和允许共享的实时状态需要连接星海舰桥服务或 SCM。选择暂不联网或手动离线时，只使用本机功能。
- 在线状态、舰船、位置、服务器分线和事件共享可以在设置中分别控制。隐身或暂停共享时，别人看到的和普通离线一样，不发送位置和事件。
- 从未设置过的账号进入主舰队时，默认全部共享，并提示一行，可以在设置里逐项关闭。
- 个人页的头像、名字和交易时段始终公开；隐私设置只保护下方模块。
- 游戏时长只有在用户同意后才记录，保存在本机，不是官方生涯记录。
- 交易中填写的联系方式由 SCM 保存，在 SCM 交易中可能显示给对方。
- 本地日志和诊断信息可能包含游戏 ID、服务器标识、地点代码、文件路径或其他个人信息。提交反馈前请检查并删除不希望公开的内容。
- 应用不会要求或保存 RSI 账号密码。内置网页及第三方页面受对应网站的账号与隐私规则约束。

请在“设置 → 同步与隐私”中确认共享范围。

### 从公开源码构建

需要 Windows、.NET 8 SDK、Flutter 3.47.2（Dart 3.13.2）、Visual Studio 的“使用 C++ 的桌面开发”和 Windows SDK。Flutter 插件需要开启 Windows 开发者模式，或系统允许创建目录符号链接。不需要生产密钥、私有数据或托管服务源码。

```powershell
pwsh -NoProfile -File "scripts/Test StarBridge Public Client.ps1" -MenuOverlay
```

这个入口会还原固定依赖和 WebView2 SDK，运行公开版的 .NET 和 Flutter 回归测试，再构建启用菜单浮层的 Windows 客户端，输出在 `StarBridge.Flutter/build/windows/x64/runner/Release/`。自行调用 Flutter 构建时，需要传入 `--dart-define=STARBRIDGE_ENABLE_MENU_OVERLAY=true`。

**验证状态：**

- 公开 CI 运行上面的入口。0.7.2 的公开 CI 没有全部通过：Core、Host 通过，Flutter 有 12 项失败（测试在 UTC 时区下的问题，0.7.2.1 已修），Windows 构建步骤没跑到。维护者当时决定不等 CI 通过就发布。
- 0.7.2.1 的实际 CI 结果见[公开 CI](https://github.com/Domino-L/StarBridge-OpenCore/actions/workflows/validate.yml)。本版须整轮通过后才激活更新通道或转为正式 Release；本地校验不等于公开 CI 通过。
- 公开版的浮层动画测试在机器负载高时可能不稳定。

公开源码不带游戏截图、背景媒体和专有素材的视觉基线，公开测试模式会跳过这些截图比较。缺少可选媒体时使用中性占位，不需要从其他仓库复制素材。少量由控件和合成数据生成的测试图见 [测试图说明](docs/UI_TEST_FIXTURES.md)，不含真实聊天或账号截图。

源码构建通过不代表已经发布。官方安装包的发布状态以本页下载区和 Releases 为准。

菜单浏览器与内置 RSI 机库读取器使用 WebView2 SDK 1.0.3179.45，上述入口会自动从官方 NuGet 源还原，也可以通过 CMake 变量 `STARBRIDGE_WEBVIEW2_SDK_ROOT` 指向合法安装的 SDK。未提供时客户端仍可构建，读取器会明确显示不可用。

### 源码结构

| 模块 | 职责 |
| --- | --- |
| `StarBridge.Flutter` | 客户端界面、状态、交互与 Windows Runner。 |
| `StarBridge.NativeBridge` | 客户端与本机服务的公开通信约定。 |
| `StarBridge.HostRuntime` / `StarBridge.NativeHost` | 本机持久化、日志读取、托盘和通知等 Windows 能力，以及远端接口的客户端适配。 |
| `StarBridge.OverlayRuntime.Windows` | 信息浮层的 Windows 渲染。 |
| `StarBridge.Core` | 公开领域规则与日志解析。 |
| `StarBridge.UpdateHelper` | 本机受校验的更新流程，不是云端发布服务。 |

本仓库不包含云端业务实现、服务端数据库、生产部署或签名私钥。远端功能需要合法账号及相应服务权限，公开客户端不会绕过授权。
